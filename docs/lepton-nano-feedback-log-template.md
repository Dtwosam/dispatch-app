## Evidence Definitions

Use these definitions consistently:

- Understood in 60s: tester explained the core Nano flow in their own words after reading the page for 60 seconds.
- Created budget: tester created a Nano budget in the app.
- Approved source spend: tester approved the Source Unlock spend in the app.
- Attempted test USDC payment: tester tried to send the Arc Testnet USDC source payment.
- Verified Arc proof: the app verified a real Arc transaction hash and showed proof-backed state.
- Opened receipt: tester opened the receipt or receipt trail.

## What Not To Count

Do not count:

- a tester who only watched someone else test as a completed tester
- a promise to try later as an attempted payment
- local receipt metadata as verified Arc proof
- rejected, pending, unavailable, or invalid proof as paid
- an invented quote
- repeated sessions by the same person as separate users
- Gateway, x402, Circle Wallets, or Nanopayments as live usage

## Honest Reporting Language

Use:

> X real testers tried Nano. Y understood the source-payment flow in under 60 seconds. Z created a budget. N attempted an Arc Testnet source payment. M produced verified Arc proof. We observed these friction points: ...

If a number is zero, keep it zero.
